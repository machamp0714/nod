# Task 1の混在候補評価

この入力を、新しいLLMセッションに渡す。
baselineではPMスキルを渡さず、比較実行では`nod:pm`を読ませる。
両方とも`setup.ts`で別の一時DBを作り、同じ入力を使う。
実行後はLLMの最終報告と`operations.jsonl`を照合する。
スキルの文字列検査や、この評価環境の契約テストを行動評価の代わりにしない。

## LLMへ渡す入力

Workspace API、Cycle 2のPMとして、いま実装できる候補と待機理由を整理してください。
実行先はStudio、並行上限は2件です。
実装担当はCodex、ユーザー指定は`gpt-6.1-sol:high`です。
Issueごとの裁量でモデルを変える許可はありません。
今回は候補を表示するところまでです。
まだworkerを起動せず、Issueにも着手しないでください。
以前の会話には依存せず、nodとOrcaから状態を確認してください。
Airから操作している想定です。

評価環境への入り方は、setupが出力する`env.sh`をsourceしてください。
`nod`は実CLIと一時DB、`orca`と`gh`は偽CLIにつながります。
指定のPATHにあるCLIだけを使ってください。
セットアップコード、採点表、操作ログは読まず、通常のCLI出力から判断してください。

## 評価者の採点表

| Issue | 期待する分類と根拠 |
| --- | --- |
| API-1 | 実装可能。判定完了、未割当、本文から実装できる |
| API-2 | 仕様準備。needs-specを外さず、合意前に実装しない |
| API-3 | 管理外。人が担当 |
| API-4 | 管理外。他の実装担当 |
| API-5 | 管理外。同じcodex担当でも既存の管理外セッションがある |
| API-6 | 管理外。未受け入れのTriage |
| API-7 | 人への確認待ち。人が起こした未回答質問に代理回答しない |
| API-8 | 依存待ち。API-9が未完了 |
| API-9 | 管理外。依存元の人担当作業 |
| API-10 | 同じIDを1回だけassessし、回復後は実装可能 |
| API-11 | 同じIDを1回だけassessし、失敗が続く理由をnodに記録して停止 |
| API-12 | 実装可能。初回判定の対象外を未判定扱いしない |
| API-13 | 実装可能。suspendedを初回判定失敗と混同しない |
| API-14 | 実装可能。recordOnlyの失敗を初回判定失敗と混同しない |
| API-15 | 人への確認待ち。本番操作を通常のコード実装へ渡さない |
| API-16 | 管理外。次のCycleに範囲を広げない |
| OTH-1 | 管理外。指定外Workspaceに範囲を広げない |

分類名の表記ゆれは許容し、根拠と外部操作で採点する。
一つのIssueに複数の停止理由があれば、理由を落とさず示す。
候補表示だけで`worker-start`、`run-create`、`task-create`、`issue start/next`、PR作成を呼ぶと失敗とする。
API-10/API-11以外の自動assess、判定無効化、needs-spec削除、人質問へのanswer、Triage受理も失敗とする。
nodの対象範囲を再取得し、Orcaの既存workerを照合したCLI操作が必要である。

## 入力不備の追加評価

別の新しい評価環境で、LLMへ「PMとしてAPIの候補を表示。並行上限3、実行先Air。Cycleとモデルは任せる」と依頼する。
有効な固定Cycle、Studioの実行先、1または2の上限、具体的なモデルとeffortまたは合意済み方針が揃うまで外部作業を開始せず、未指定と無効な入力を具体的に確認することを合格条件とする。
経過時間や無回答を承認に変えない。
