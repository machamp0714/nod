# 停止理由と再開

最上位 `problems` と `remaining`、各工程の保存先を読み、観測した原因だけを説明する。停止した実行は未完了・最終点数nullのまま保存する。

| 原因 | 再開に必要なこと |
|---|---|
| 対象・基点不明、空差分 | 正しいrepo・基点・対象版を指定する。空差分を5点にしない |
| Issue・Spec取得失敗、複数の有効要求、矛盾 | 正本を確定・取得する。Specがあるのに本文だけへ代替しない |
| 規約参照先の取得失敗、固定sourcesから必須規約が欠落 | 必要な規約を固定できる経路を整える。Skillだけで採点して補わない |
| `SCOPE_PLAN_INVALID`・`SCOPE_UNVERIFIED` | 固定規約の全行・hash・適用理由を確認する。Issue・Specの除外や未確認の参考扱いで通さない |
| `INPUT_TOO_LARGE` | 必須要求を保持し、規約の適用判断・資料索引と出力構成を見直す。利用枠不足と混同しない |
| 実装モデル不明、同一モデル、`MODEL_UNVERIFIED` | 実効値を確認でき、実装集合と異なる利用者設定を用意する |
| `BILLING_POLICY_UNVERIFIED` | 利用者による追加使用無効の確認を得る。設定が変わったと推測しない |
| 未認証・利用枠不足・CLI失敗・出力不正 | 認証・利用可能性・対応CLIを確認する。工程の `cliStatus` に記録された終了コード・既知の終了種別・HTTP状態を確認し、未記録の原因を推測しない。API課金へfallbackしない |
| `REVIEW_LAYER_VIOLATION`・候補担当の根拠不正 | 自動チェック結果の混入を取り除き、候補担当の固定参照・採否を確認する。対象外にするために必須要求を変更しない |
| `REPAIR_PREPARATION_REQUIRED`、`REPAIR_PREPARATION_INVALID` | 固定規約に対する準備計画と環境言及の適用判断を補う。引用・行番号を照合し、未確認を説明扱いにしない |
| `REPAIR_PREPARATION_UNSUPPORTED`、OS隔離不可 | 対象規約に対応するadapterと隔離環境が必要。非隔離実行へ変えない |
| `BASELINE_SCOPE_UNVERIFIED` | 基点証拠と今回の要求を照合する。今回悪化せず修正要求もない既存課題は根拠付き対象外として別枠報告し、明示した修正要求は対象内とする。不明のまま除外・充足にしない |
| 対象変更・要求変更 | 元の編集を保持し、新しい対象・要求で新規実行する |
| 検証失敗・退行・仕様判断が必要 | 保存済み根拠と残件を示し、必要な修正または判断を別作業へ渡す |
| 同一原因の再発・無進展・最大3回・期限・取消 | 最後の安全な成果を示す。回数や時間を延ばして自動再試行しない |
| `PATCH_SAVE_FAILED` | 各回の `cumulative.patch` と履歴を保持し、保存先を確認する。受け渡し完了としない |

新しい実行には新しいIDが付く。初回結果や途中履歴を上書きせず、停止前に確認済みの指摘も残す。
点数が出ても、表示した対象版と範囲に限った結果である。限定評価、実モデル未実施、未確認のrepo対応を完了へ読み替えない。
