# レビュー結果

担当は自分の工程の情報だけを返す。
探索担当の返答は中間報告であり、検証担当へ中継する本文ではない。
検証担当は許可入力と自分の記録結果だけを使い、探索担当の識別情報を取りに行かない。
両担当の組と最終保存の照合は親が統合報告で埋める。
不明な値を推測せず「不明」、未記録は「未記録」とする。

## 実行と対象

- 工程：探索／検証／親の統合報告
- runId：
- 保存ディレクトリ：
- 探索記録パス／最終検証記録パス：
- 独立レビュー：未実施（理由）／実施済み完了／実施済み記録済み未完了
- CLI状態：prepared／planned／explored／exploration_incomplete／completed／incomplete
- 対象：repo、基点、merge-base、head SHA、mode、target.hash（localならtree SHAも）
- 要求と規約：Issue、Document、計画、規約の出典と版
- 確認範囲：全体／限定範囲、適用計画、残る要求、scopePolicy
- 最終点数：0〜5／点数なし（中間状態と最終未完了はnull）
- 固定版の結果と現在版への提出可否：fixedResult／currentSubmission

## 担当の識別

| 工程 | 定義名 | 担当ID（親が委譲結果から対応付け） | モデル申告 | 出典 | 申告状態 |
|---|---|---|---|---|---|
| 探索 | | | | | declared／unverified |
| 検証 | | | | | declared／unverified |

申告不明はvalue=null、source=nullとし、実効値の証明や要求未確認と混同しない。
親は両担当IDを同じrunId、保存先、対象版へ対応付ける。
担当IDの違いだけを会話履歴の非継承の証明としない。
検証担当の初期入力に工程、runId、保存先以外が入っていないことの観測は、親側の証跡として別に示す。

## StandardsとSpec

両軸それぞれの完了状態と要対応件数を記載する。
各指摘に元の軸付きID、原因ID、場所、契約出典、到達条件、期待動作、実際の破綻、影響、固定証拠、採否と理由を付ける。
同一原因に関連付けても、各軸の出典や採否を消さない。

## 要求ごとの確認

| 要求IDと固定出典 | 判定（充足／未充足／未確認／対象外／context） | 本文分類と根拠 | 実装箇所 | 静的な確認方法と証拠 | 指摘との対応と除外根拠 |
|---|---|---|---|---|---|

contextは説明の確認であり、実装の充足件数へ加えない。
元の軸付き候補IDを使い、違反、補足、棄却、未確認の対応を区別する。
要求対応が長ければ全文の報告をCLI保存先または一時ファイルへ保存し、リンクを返す。
チャットの要約で要求別記録を置き換えない。

## 対象外の課題

| 候補IDと場所 | 課題と影響 | 基点の固定証拠 | 今回の変更や要求と無関係とする根拠と出典 | 責務と扱い |
|---|---|---|---|---|

該当なしは「なし」とする。
無関係な既存課題は未解決の事実を残し、「今回の採点と未完了判定の対象外」と記載する。
自動チェック担当の候補はその責務を示す。
混入したoptionalは保存記録へ保持し、通常の報告で提案しない。

## 未確認と残件

確認済み要対応、必須確認の不足、要求の矛盾や変化、停止理由と必要条件、保存済み成果を示す。
自動チェックを実行または受領したかのような証拠を載せない。
探索のみなら「探索のみ、レビュー未完了、点数なし」と明示する。
最終記録なしなら未実施の理由と取得済み識別情報を示し、記録済みincompleteと区別する。
修正は親側の別作業であり、この報告を対象変更の許可や別commitの承認、マージ許可にしない。
