### 後続判断

未実施・未完了なら原因（未完了なら有効な結果が無い担当と理由。利用枠の上限ならそのこと）・試行の記録・受領済みの成果・取得できた担当 ID と、Done・In Review・PR へ進めないこと（委譲し直しや利用枠の回復待ちで代替しないこと）。完了なら確定した要対応の点数と要対応の有無、確認が残る事項の件数。いずれもマージ可否と、不可なら人の判断が要ること。完了でもマージ不可なら、確認が残る事項を提出・完了に必要な確認の不足として既存の提出・完了条件へ委ねること。

### 独立性の限界

探索と反証は別コンテキストで実行し、探索には異なるモデルを設定するが、見落としが共通する可能性は残り、設定だけで各実行の実効モデルの違いを証明するものではない。

- この実行のロール設定: Standards 探索 `<review-standards の設定>`、Spec 探索 `<review-spec の設定>`、反証 `<review-refute の設定>`、受け入れ確認 `<review-acceptance の設定>`（起動したときだけ）（出典: ハーネスが示した担当の設定。分からなければ未確認）。2つの探索ロールが同じモデルに設定されていた場合（比較用に揃えた設定など）は、「この実行では探索の2担当は同じモデルの設定であり、モデルの違いによる独立性は無い」と書き添える。
