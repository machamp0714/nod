- 確認が残る事項: N 件（下の「確認が残る事項」の節）。最終状態と点数を変えず、マージ可否だけを止める。
- マージ可否: 可（人のレビューなしでマージ可）／不可（人の判断が要る）
  - 可は、次のすべてを満たすときだけ。最終状態が完了で確定した要対応の点数が 5／対応表のすべての行が充足・説明・対象外のどれか、または同じ head SHA のテスト実行が成功した自動チェック担当の行、または受け入れ確認担当が確認済みとした行／確認が残る事項が0件／同じ head SHA の別 checkout でのテスト実行が成功。可でもリポジトリの既存のマージ条件は省かない。
  - 不可の理由: 最終状態とその理由／確定した要対応の点数または点数なし／テスト実行の判定と、checkout の SHA が head の SHA と一致するか／確認が残る事項（すべて。下の節）

### 後続判断

未実施・未完了なら原因（未完了なら有効な結果が無い担当）・受領済みの成果・取得できた担当 ID と、Done・In Review・PR へ進めないこと。完了なら確定した要対応の点数と要対応の有無、確認が残る事項の件数。いずれもマージ可否と、不可なら人の判断が要ること。完了でもマージ不可なら、確認が残る事項を提出・完了に必要な確認の不足として既存の提出・完了条件へ委ねること。

### 独立性の限界

探索と反証は別コンテキストで実行し、探索には異なるモデルを設定するが、見落としが共通する可能性は残り、設定だけで各実行の実効モデルの違いを証明するものではない。

- この実行のロール設定: Standards 探索 `<review-standards の設定>`、Spec 探索 `<review-spec の設定>`、反証 `<review-refute の設定>`（出典: ハーネスが示した担当の設定。分からなければ未確認）。2つの探索ロールが同じモデルに設定されていた場合（比較用に揃えた設定など）は、「この実行では探索の2担当は同じモデルの設定であり、モデルの違いによる独立性は無い」と書き添える。
