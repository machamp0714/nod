# 反証の判定

## 担当と対象

- 役割: 反証
- 定義名: code-reviewer-refute
- 担当 ID: （分かれば。分からなければ「不明」）
- モデル申告: （自分で分かる情報と出典。分からなければ「未確認」）
- 対象版: repo の絶対パス／mode／merge-base の SHA／head の SHA（mode: local なら土台の HEAD と `local/` の各ファイルの sha256）
- 受け取った入力: `refute-input/` の各ファイルと、`manifest.md` の sha256 との一致
- 終了状態: 完了／未確認を含む

## 軸ごとの結果

- Standards: 要対応 N 件、未確認 M 件（指摘や未確認が無くても 0 件と書く）
- Spec: 要対応 N 件、未確認 M 件（指摘や未確認が無くても 0 件と書く）

## 要対応（影響度の重い順）

要対応が無ければ「なし」。同一原因は1件にまとめ、含まれる候補 ID をすべて書く。

### <CAUSE-n または候補 ID>: <不具合を表す短い題>

- 候補 ID と発見者の区分: `STD-1`（Standards 探索）、`SPC-2`（Spec 探索）、`REF-1`（反証で追加）など
- 影響度: 0〜4
- 軸: Standards／Spec
- 起点: 今回の差分／基点から存在（基点から存在でも今回の明示要求が修正を求めるもの）
- 契約の出典:
- 関連する要求・契約:
- 場所:
- 到達条件:
- 期待動作:
- 破綻:
- 影響:
- 証拠:
- 反証の判定理由:

## 基点から存在する課題（別枠）

基点から存在（対象外）と判定した課題。候補 ID・場所・課題と影響・merge-base の証拠・今回の差分と要求との関係（悪化させていない、修正を求められていない根拠）。なければ「なし」。

## 要求ごとの対応表（確定）

Spec 探索の対応表のすべての行を確定する。足した行は証拠または不足理由の欄にその旨を書く。

| 要求の出典 | 状態 | 証拠または不足理由 | 候補ID |
|---|---|---|---|

## 未確認と理由

採否や充足を確定できなかった候補・要求、要求間の矛盾ごとに、要求の出典（または候補 ID）・理由（実行しないと分からない挙動は「要実行確認」）・確かめる担当（例: 人）・不足箇所を書く。なければ「なし」。

## 判断を見送った事項

1件ごとに短い理由。なければ「なし」。

## 採否一覧（監査用）

両方の引き渡し用ファイルのすべての候補と、反証で追加した発見を載せる。任意の改善はここにだけ載せ、提案として扱わない。

|---|---|---|---|---|---|
