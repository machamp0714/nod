# 反証の判定

## 担当と対象

- 役割: 反証
- 定義名: code-reviewer-refute
- 担当 ID: （分かれば。分からなければ「不明」）
- モデル申告: （自分で分かる情報と出典。分からなければ「未確認」）
- 対象版: 対象リポジトリ（`target.md` の担当用の限定 clone）の絶対パス／mode／merge-base の SHA／head の SHA（mode: local なら土台の HEAD と `local/` の各ファイルの sha256）
- 受け取った入力: `refute-input/` の各ファイルと、`manifest.md` の sha256 との一致
- 依存の写し: 依頼本文が示す場所、`manifest.md` の lockfile のパスと sha256、`deps-files.sha256` と `manifest.md` の sha256 との一致（準備されていなければ「依存の写しなし」と `manifest.md` の理由）
- 終了状態: 完了／未確認を含む

## 軸ごとの結果

要対応の件数は下の要対応の節のその軸の見出しの数（同一原因は1件）、未確認の件数は未確認と理由の表のその軸の行数と同じにする（親のスクリプトが照合する）。

- Standards: 要対応 N 件、未確認 M 件（指摘や未確認が無くても 0 件と書く）
- Spec: 要対応 N 件、未確認 M 件（指摘や未確認が無くても 0 件と書く）

## 要対応（影響度の重い順）

要対応が無ければ「なし」。同一原因は1件にまとめ、含まれる候補 ID をすべて書く。見出しは `CAUSE-<n>`（採否一覧の同一原因と同じ）か候補 ID で始める。同一原因の影響度は、含まれる要対応の候補の採否一覧の影響度のうち最も重いもの（最小値）にする。

### <CAUSE-n または候補 ID>: <不具合を表す短い題>

- 影響度: 0〜4
- 軸: Standards／Spec
- 起点: 今回の差分／基点から存在（基点から存在でも今回の明示要求が修正を求めるもの）

## 基点から存在する課題（別枠）

基点から存在（対象外）と判定した課題。候補 ID・場所・課題と影響・merge-base の証拠・今回の差分と要求との関係（悪化させていない、修正を求められていない根拠）。なければ「なし」。

## 要求ごとの対応表（確定）

Spec 探索の対応表のすべての行を確定する。足した行は証拠または不足理由の欄にその旨を書く。

| 要求の出典 | 状態 | 証拠または不足理由 | 候補ID |
|---|---|---|---|

## 分割・追加した行

対応表（確定）の行のうち、要求の出典が Spec 探索の対応表の行と一字も同じでないもの（複合要求を分けた行と、足した行）を1行ずつ、対応表と同じ要求の出典で書く。分割元の出典には、分けた元の Spec 探索の対応表の行の要求の出典をそのまま写し、足した行は「なし（追加）」と書く。Spec 探索の対応表の各行は、同じ出典の行が対応表にあるか、ここで分割元の出典になっていなければならない。なければ「なし」。

| 要求の出典 | 分割元の出典 |
|---|---|

## 受け入れ確認担当の行

対応表で「受け入れ確認担当」とした行を1行ずつ、対応表と同じ要求の出典で書く。複合要求のコードから判断できる部分は対応表の別の行で判定し、ここには書かない。必要な外部の正本の欄には、要求が一致や更新順序を求める Git 外の正本（デザインなど）について、要求の原文が示す出典の場所（絶対パス・URL・Document ID・Git のリポジトリのパスと revision）と版、更新順序を求める行では版履歴の出典を書く（親はこの欄に書かれた場所だけを写す）。原文に場所が無ければ「出典の場所の記載なし」と書く。Issue の作業ログ・添付 Document と、それらが参照する成果物・記録は親が別に写すので書かない。なければ「なし」。

| 要求の出典 | 確かめること（成果物） | 確かめること（作業・手順・配置） | 必要な外部の正本（出典の場所・版・版履歴の出典。要らなければ「なし」） |
|---|---|---|---|

## 未確認と理由

採否や充足を確定できなかった候補・要求、要求間の矛盾を、自由記述ではなく次の表に1件1行で書く。種別は「候補」（採否一覧で判定が未確認の候補。出典の欄に候補 ID を1つ）・「要求」（対応表で状態が未確認の行。出典の欄に対応表と同じ要求の出典を1つ）・「要求間の矛盾」（矛盾で未確認にした対応表の行。行ごとに1行）のどれか。判定が未確認のすべての候補（受け入れ確認担当の行で確かめる候補を含む）と、状態が未確認の対応表のすべての行を載せる。理由（実行しないと分からない挙動は「要実行確認」）・確かめる担当（例: 人）・不足箇所は空にしない。状態が「受け入れ確認担当」の対応表の行は書かない。なければ「なし」。

| 要求の出典または候補ID | 軸 | 種別 | 理由 | 確かめる担当 | 不足箇所 |
|---|---|---|---|---|---|

## 判断を見送った事項

1件ごとに短い理由。なければ「なし」。

## 採否一覧（監査用）

両方の引き渡し用ファイルのすべての候補と、反証で追加した発見を載せる。任意の改善はここにだけ載せ、提案として扱わない。影響度は要対応にだけ 0〜4 を書き、それ以外は「なし」と書く。反証で追加した発見が無ければ、この節に「反証で追加した発見なし」と書く。

| 候補 ID | 発見者の区分 | 判定（要対応／棄却／未確認／基点から存在（対象外）／任意） | 影響度 | 同一原因 | 根拠 |
|---|---|---|---|---|---|
