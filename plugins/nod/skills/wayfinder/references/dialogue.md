# 対話と別モデル照合の記録

## Document を先に用意する

`nod doc list` で既存の対話記録を探し、再開時は同じ Document を使う。
子がある場合は、次の形で作成する。

```sh
nod doc create <子IDの小文字>-wayfinder-YYYYMMDD.md --title "<子のタイトル>：対話記録" --kind doc --issue <子ID> --body "<前提と照会先>"
```

新規マップの到達点を決める対話では、`--issue` を付けずに `wayfinder-<短い名前>-YYYYMMDD.md` を作る。
親を起票したら `nod doc link <Document ID> --issue <マップID>` で紐付ける。
一時ディレクトリのファイルを永続記録として添付しない。
nod が作った Markdown のパスを確認して編集し、同名の記録を作り直さない。

冒頭に、到達点、既に確定した前提、照会先のモデル・effort を書く。
最終回答の正本は子の解決コメントであり、この Document は対話と検証の履歴とする。

## 独立照合

自分の推奨を Document に先に書き、別モデルにはそれを見せず、問い・Issue 本文・確定済みの判断だけを渡す。
ログを丸ごと渡して自分の未確定の推奨を漏らさない。
次の回答形式を求める。

- 各問への案、理由、根拠。確認していない事実は「推測」と明記する。
- 確定事項を覆す意見は「変更提案」と分ける。
- 残る重要な論点を最大三つ挙げる。実装者に任せてよい細部は含めない。
- 調査と回答のみ。ファイル・Issue の更新や外部サービスへの書き込みは行わない。

照会先は `nod:to-spec` と同じく、現在の実行環境と異なるモデルを使う。

- Claude Code からは既定で gpt-6-astra・high。
- Codex からは既定で opus。Claude CLI に対応する effort オプションを確認できない場合、effort を指定したと偽らない。
- ユーザーがモデルを指定した場合はそれを優先する。

```sh
# Claude Code からの照会
codex exec -m <model> -c model_reasoning_effort=<effort> -s read-only --skip-git-repo-check -o <回答ファイル> - < <プロンプトファイル>

# Codex からの照会
claude -p --permission-mode plan --model <model> < <プロンプトファイル> > <回答ファイル>
```

照会用ファイルは一時置きでよいが、返答と採用根拠は Document に保存する。
CLI が使えない、失敗する、長時間返らない場合は独立照合できなかったと明記し、同じ照会を無限に繰り返さない。
照合できないことだけで人との対話を停止せず、確認できた根拠と不確実性を示して質問する。
別モデルを実行していないのに「両モデル一致」と記録しない。

## 人に示す形

前提が揃った問いを一ラウンドにまとめ、推奨案と短い理由を添える。
別の未回答に依存する問いは、このラウンドには入れない。

```markdown
❓ **Q1 — 判断したいこと**

具体的な選択肢と、どの場面の判断なのか。

➡️ 推奨案と理由。別モデルとの相違があれば、もう一案と根拠も示す。
```

**一致した案でも、人の回答前は未決定。** 「はい」「全部はい」などは、提示済みの推奨案への回答として記録できる。
以前に合意したことは新たな質問にせず、今回の前提として示す。
合意内容を変える提案は、通常の未決の問いと区別する。

ラウンドごとに次の表を追記し、照会先の回答原文は `<details>` に保存する。

| 問い | 自分の推奨と根拠 | 照会先の案 | ユーザーの回答 | 決定・残る点 |
| --- | --- | --- | --- | --- |

ユーザーの未回答を空欄のまま確定にしない。
前提の訂正・判断の見直しは、変更した内容と理由を追記して履歴を保つ。
問いがなくなったら判断と残る制約をまとめ、合意を確認して子の解決コメントへ記録する。
